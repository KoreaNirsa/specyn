# 목적
앞으로의 모든 Specyn 작업을 TDD 기반으로 진행하기 위한 스펙 기준을 정의한다.

# 입력
## 핵심 시나리오
- 작업자는 구현 전에 실패해야 하는 테스트 또는 검증 명령을 먼저 정의한다.
- 구현자는 실패를 확인한 뒤 최소 변경으로 테스트를 통과시킨다.
- 리뷰어는 테스트 없이 포함된 구현 변경을 blocker로 분류한다.
- 스펙 변경은 테스트 기대값 변경과 함께 검토된다.

## 비기능 요구사항
- 모든 구현 작업은 Red, Green, Refactor 순서를 따른다.
- 테스트가 불가능한 항목은 이유와 대체 검증 방법을 스펙에 남긴다.
- 스펙에 없는 기능을 테스트나 구현에 추가하지 않는다.
- 회귀 테스트는 변경 범위와 위험도에 맞춰 최소 충분하게 작성한다.

## 제외 범위
- 테스트 없이 진행하는 구현
- 스펙에 없는 기능의 선제 구현
- 전체 구조 리팩터링
- 외부 시스템을 요구하는 불안정한 테스트 강제

# 출력
- TDD 작업 원칙
- 테스트 선행 기준
- 스펙 보완 기준
- 리뷰 gate 기준

# 실행 규칙
1. 구현 전 실패 테스트 또는 검증 기준을 먼저 작성한다.
2. 실패 확인 없이 구현부터 진행하지 않는다.
3. 테스트가 불가능하면 스펙에 보류 사유와 수동 검증 기준을 남긴다.
4. 테스트 통과 후에만 리팩터링을 수행한다.

# Validation 기준
- 핵심 시나리오는 3개 이상이어야 한다.
- 비기능 요구사항은 4개 이상이어야 한다.
- 제외 범위가 명시되어야 한다.
- Red, Green, Refactor 순서가 포함되어야 한다.

# Prompt
## Role
당신은 Planner Agent로서 모든 향후 작업의 TDD 기준을 정의한다.

## Instructions
1. 테스트 선행 원칙을 작업 흐름에 고정한다.
2. 테스트 불가능 항목의 보류 기준을 명확히 한다.
3. 구현 범위는 스펙과 테스트로 제한한다.

## Format
1. TDD principles
2. workflow gates
3. exception handling
4. review criteria
